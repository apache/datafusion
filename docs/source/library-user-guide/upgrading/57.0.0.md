# Upgrade Guides

## DataFusion 57.0.0

**Note:** DataFusion `57.0.0` has not been released yet. The information provided
in this section pertains to features and changes that have already been merged
to the main branch and are awaiting release in this version.

### Range partitioning accepts equal split points

`datafusion_common::validate_range_split_points` and the logical and physical
`RangePartitioning` constructors now accept equal adjacent split points.
Previously, split points had to be strictly ordered; they must now be
non-decreasing according to the supplied sort options. Equal adjacent split
points describe empty partitions. Keys equal to a repeated split point go to the
partition after its last occurrence.

Callers that relied on duplicate rejection must additionally reject adjacent
points that compare equal under those sort options.

### Substrait consumers use explicit scope context

Add a final `&SubstraitConsumerContext` argument to custom relation and expression
callbacks on `SubstraitConsumer`. Forward it when calling conversion helpers or
consuming child relations and expressions.

Remove implementations of `push_outer_schema`, `pop_outer_schema`,
`get_outer_schema`, `push_lambda_parameters`, `pop_lambda_parameters`, and
`lambda_variable`, and remove embedded `DefaultSubstraitLambdaConsumer` values.
Use the context's `get_outer_schema` and `lambda_variable` methods to resolve
outer references and lambda parameters. To enter a scope, derive a child with
`context.with_outer_schema(...)` or `context.with_lambda_parameters(...)` and pass
it to nested conversions. No pop operation is needed; the parent stays unchanged.

`from_substrait_plan` and `from_substrait_plan_with_consumer` create the root
context. For a new conversion started directly through a helper, pass
`&SubstraitConsumerContext::default()`. Nested conversions must receive the current
context.

Custom scoped values can be stored with `context.with_extension(Arc::new(value))`
and retrieved with `context.get_extension::<MyScope>()`. Pass the returned child
context to nested conversions. Children inherit values; replacing a value leaves
parents and siblings unchanged. The values themselves are shared through `Arc`.

Update logical-plan snapshots if needed: generated lambda parameter names are
local to lexical scopes, so sibling lambdas may reuse names.

### NULL results of set-monotonic aggregate UDFs

A UDAF that returns `SetMonotonicity::Increasing` or `Decreasing` must return a
non-NULL result once it has seen a non-NULL input, and must not go back to NULL as
more inputs are added. Window ordering inference relies on this; see `SetMonotonicity`.

`AggregateFunctionExpr::get_result_ordering` now describes an ever-expanding
frame with `NULLS FIRST`. `PlainAggregateWindowExpr::add_equal_orderings` is
deprecated because it does not check the frame bounds or FILTER predicate;
inspect the window execution plan's equivalence properties instead.

### `GroupClusteringMode::Full` no longer implies sorted input

`AggregateExec` can now select `GroupClusteringMode::Full` when the input's
equivalence properties declare the complete `GROUP BY` tuple as grouped
(contiguous within each partition), even if the input is not sorted.

`Full` describes group contiguity only. Code that previously used
`group_clustering_mode() == GroupClusteringMode::Full` to infer sorted input or
output should use `properties().output_ordering()` on the input or aggregate
plan, respectively.

### `datafusion-spark` moved to its own repository

The `datafusion-spark` crate is now developed and released in
[apache/datafusion-spark](https://github.com/apache/datafusion-spark), starting
with `57.0.0`. The crate name is unchanged.

`datafusion-cli` no longer has a `--spark` flag. The Spark SQL dialect is still
available without the Spark function library:

```sql
SET datafusion.sql_parser.dialect = 'spark';
```

### `ParquetFileReaderFactory` adds `Any` as a supertrait

To enable downcasting of `dyn ParquetFileReaderFactory` to concrete factory
types (via `is::<T>()` / `downcast_ref::<T>()`), the
`ParquetFileReaderFactory` trait now has `Any` as a supertrait:

```diff
- pub trait ParquetFileReaderFactory: Debug + Send + Sync + 'static
+ pub trait ParquetFileReaderFactory: Any + Debug + Send + Sync
```

The trait already required `'static`, which `Any` implies, so existing
implementations need no changes. `ParquetSource::parquet_file_reader_factory`
returns the trait object to downcast.

### `COPY TO` ordering

`COPY TO` no longer guarantees preservation of its input's ordering. Add an
explicit `ORDER BY` when output order matters.

Previously, if `t` had an existing output ordering of `ORDER BY c1`, the `COPY TO`
statement could infer and maintain that order in the written file.

```txt
COPY (SELECT * FROM t) TO 'ordered.parquet';
```

Now, an explicit `ORDER BY c1` clause is required to preserve this behavior. In
this case, no extra sorting is needed during execution; this is a syntax change
that aligns with the SQL specification.

```txt
COPY (SELECT * FROM t ORDER BY c1) TO 'ordered.parquet';
```

### Deprecated `Expr::Wildcard` has been removed

`Expr::Wildcard` has been deprecated since version 46.0.0, and has been removed.
For counting rows, use `count_all()` or `count_all_window()`.

It has also been removed from the Protobuf and Substrait based serialization.

### Statistics must have one `ColumnStatistics` per schema field

Planning now fails with an error if an `ExecutionPlan` or `StatisticsProvider`
reports a different number of `Statistics::column_statistics` than its schema
has fields. Before, this could panic or return another column's values.

Start from `Statistics::new_unknown`, or project a child's statistics with
`Statistics::project` if the plan changes its columns:

```rust,ignore
let statistics = Statistics::new_unknown(&self.schema())
    .with_num_rows(Precision::Exact(num_rows));
```

### Materialized CTE scans have a projection

`MaterializedCteScan` and `MaterializedCteScanExec` have a `projection`. It gives
the indexes of the columns of the CTE body that the scan outputs. `None` means all
the columns. `OptimizeProjections` uses it to remove from the body the columns
that no scan reads.

A custom optimizer rule that changes the schema of the body of a
`MaterializedCte` must also change the `projection` of every scan of that CTE,
because a scan reads the columns of the body by position. Use
`MaterializedCteScan::with_body_columns` to remap a scan, and
`MaterializedCteScan::with_body_schema` to give a scan the new types of the
columns that it reads.

The `schema` and `projection` fields of `MaterializedCteScan` are private, so
that the two always match. Read them with `MaterializedCteScan::schema` and
`MaterializedCteScan::projection`. Build a scan with `MaterializedCteScan::new`
and `MaterializedCteScan::with_projection`. To build a physical scan with a
projection, use `MaterializedCteScanExec::with_body_projection`. It returns an
error if the projection does not have one index for each column of the scan
schema.

`LogicalPlan::check_invariants` checks that each scan of a `MaterializedCte`
has the names and types of the columns that it reads from the body. The
optimizer runs this check after each rule in debug builds, so a custom rule
that does not remap the scans now fails with an error that names the rule.
