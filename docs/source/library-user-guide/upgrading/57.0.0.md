# Upgrade Guides

## DataFusion 57.0.0

**Note:** DataFusion `57.0.0` has not been released yet. The information provided
in this section pertains to features and changes that have already been merged
to the main branch and are awaiting release in this version.

### Time travel queries

DataFusion now supports time travel queries such as
`SELECT * FROM t VERSION AS OF 3`. `SchemaProvider` gained a `table_at` method
that catalogs implement to return a specific version of a table, and
`TableProvider` and `TableSource` gained a `version` method that reports the
version a table reads. All have default implementations. See the
[catalog guide](../catalogs.md#time-travel) for details.

**Who is affected:**

- Implementations of `SchemaProvider::table_at` must return a provider whose
  `TableProvider::version` reports the version it reads. `ListingTable`,
  `MemTable`, `ViewTable` and `EmptyTable` support this with `with_version`.
- Custom `ContextProvider` implementations that implement
  `get_table_source_at` must return a source whose `version` reports the
  version it reads.
- Users serializing logical plans with `datafusion-proto`: the
  `ListingTableScanNode`, `ViewTableScanNode`, `CustomTableScanNode` and
  `EmptyTableScanNode` messages gained a `version` field. A
  `LogicalExtensionCodec` must restore the version of the table providers it
  decodes, or decoding fails.
