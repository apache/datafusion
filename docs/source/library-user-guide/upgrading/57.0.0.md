# Upgrade Guides

## DataFusion 57.0.0

**Note:** DataFusion `57.0.0` has not been released yet. The information provided
in this section pertains to features and changes that have already been merged
to the main branch and are awaiting release in this version.

### Substrait consumers use explicit scope context

Add a final `&SubstraitConsumerContext` argument to custom relation and expression
callbacks on `SubstraitConsumer`. Forward it when calling conversion helpers or
consuming child relations and expressions.

Remove implementations of `push_outer_schema`, `pop_outer_schema`,
`get_outer_schema`, `push_lambda_parameters`, `pop_lambda_parameters`, and
`lambda_variable`, and remove embedded `DefaultSubstraitLambdaConsumer` values.
Use the context's `get_outer_schema` and `lambda_variable` methods to resolve
outer references and lambda parameters. To enter a scope, derive a child with
`context.with_outer_schema(...)` or `context.with_lambda_parameters(...)` and pass
it to nested conversions. No pop operation is needed; the parent stays unchanged.

`from_substrait_plan` and `from_substrait_plan_with_consumer` create the root
context. For a new conversion started directly through a helper, pass
`&SubstraitConsumerContext::default()`. Nested conversions must receive the current
context.

Custom scoped values can be stored with `context.with_extension(Arc::new(value))`
and retrieved with `context.get_extension::<MyScope>()`. Pass the returned child
context to nested conversions. Children inherit values; replacing a value leaves
parents and siblings unchanged. The values themselves are shared through `Arc`.

Update logical-plan snapshots if needed: generated lambda parameter names are
local to lexical scopes, so sibling lambdas may reuse names.

### File caches include the object store URL

File listing, statistics, and Parquet metadata caches now include the registered
object store URL in their keys. This prevents identical paths in different buckets
from sharing cached results. Statistics and Parquet metadata validation requires matching size and
modification time, plus strong ETags when both metadata values provide them,
otherwise versions when both provide them. Weak HTTP ETags are treated
as missing. ETags remain opaque: differences such as quoted versus unquoted values
cause a cache miss.

`RuntimeEnv::register_object_store` and `deregister_object_store` invalidate
cached entries for that registry URL, including entries for named and anonymous
tables. Other stores retain their entries. Coordinate registration changes with
queries using that URL: in-flight queries can repopulate caches from the old
store. Direct changes to `RuntimeEnv::object_store_registry` bypass invalidation.

`FileFormat` inference signatures are unchanged. Formats can opt into a scoped
metadata cache through the default `with_file_metadata_cache` method. Parquet
inference without a configured scope reads fresh metadata.

**Migration guide:**

- `TableScopedPath` contains a `store_path: StoreScopedPath` field alongside its
  optional `table`, replacing the previous `path` field. Use
  `TableScopedPath::new(table, object_store_url, path)` to construct a key and
  `path()` to access its relative path. Store URLs are shared through `Arc`.
- `FileMetadataCache` uses `StoreScopedPath` instead of `object_store::path::Path`
  as its key. Construct keys with
  `datafusion_execution::cache::StoreScopedPath::new(object_store_url, path)`.
- `CachedParquetFileReaderFactory::new` now takes
  `(store, object_store_url, metadata_cache)`.
- `DFParquetMetadata::with_file_metadata_cache` and
  `ParquetFileReader::with_metadata_cache` take
  `Option<(Arc<FileMetadataCache>, Arc<ObjectStoreUrl>)>`. Use `Some((cache, url))`
  to enable scoped caching and `None` to disable it.

The CLI's `metadata_cache()`, `statistics_cache()`, and `list_files_cache()`
functions append an `object_store_url` column, preserving the existing column
positions. Their `path` columns remain relative to that store.

See [issue #25841](https://github.com/apache/datafusion/issues/25841) for details.
