# Upgrade Guides

## DataFusion 57.0.0

**Note:** DataFusion `57.0.0` has not been released yet. The information provided
in this section pertains to features and changes that have already been merged
to the main branch and are awaiting release in this version.

### Time travel queries and table selectors

DataFusion now supports time travel queries such as
`SELECT * FROM t VERSION AS OF 3`. These are planned using a `TableSelector`,
which specifies which state of a table to read. `SchemaProvider` gained a
`table_with_selector` method that catalogs implement to return a table for a selector,
and `TableProvider` and `TableSource` gained a `selector` method that reports
the selector a table reads. `RelationPlanner` gained a `plan_table_selector`
method to map other SQL syntax to a selector. All have default
implementations. `RelationPlanner::plan_relation` now has a default
implementation too, so a planner that only implements `plan_table_selector`
does not need to implement it. See the [catalog guide](../catalogs.md#table-selectors-and-time-travel)
for details.

**Who is affected:**

- Implementations of `SchemaProvider::table_with_selector` must return a provider whose
  `TableProvider::selector` reports the selector it reads. `ListingTable`,
  `MemTable`, `ViewTable` and `EmptyTable` support this with `with_selector`.
- Custom `ContextProvider` implementations that implement
  `get_table_source_with_selector` must return a source whose `selector` reports the
  selector it reads. They must also implement `evaluate_const_expr` to evaluate
  the expressions of time travel clauses.
- Users serializing logical plans with `datafusion-proto`: the
  `ListingTableScanNode`, `ViewTableScanNode`, `CustomTableScanNode` and
  `EmptyTableScanNode` messages gained a `selector` field. A
  `LogicalExtensionCodec` must restore the selector of the table providers it
  decodes, or decoding fails.
